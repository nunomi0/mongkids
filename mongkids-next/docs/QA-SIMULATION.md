# QA 시뮬레이션 체크리스트 (100명 시드)

## 0) 준비

1. 시드 실행

```bash
npm run seed
```

2. 개발 서버 실행

```bash
npm run dev
```

3. 기준 날짜
- 문서 기준: `2026-02-21`
- 대시보드 월 기준: `2026-02`

## 1) 데이터 기대값 요약

- 학생 총원: `100`
- 상태 분포: 재원 `70` / 휴원 `15` / 퇴원 `10` / 체험 `5`
- 대시보드 위젯:
- 레벨 테스트 대상자: `15명 이상`
- 미처리 보강: `30건 이상`
- 오늘의 체험: `2건` (`2026-02-21`)
- 이달 미납: `30명` (`2026-02`)

## 2) 테스트 케이스 (TC-01 ~ TC-20)

### 그룹 1. 대시보드

### TC-01 요약 카드
- 전체 학생 `100명`
- 재원 `70명`
- 휴원 `15명`
- 퇴원 `10명`
- 체험 `5명`

### TC-02 대시보드 위젯
- 레벨 테스트 대상자 `15명+`
- 미처리 보강 `30건+`
- 오늘의 체험 `2건`
- 이달 미납 학생 `30명` (2026-02)

### 그룹 2. 학생 관리

### TC-03 학생 목록 필터/검색
- 상태 필터: 재원(70) / 휴원(15) / 퇴원(10)
- 이름 검색: `김` 검색 시 김씨 학생만 표시
- 레벨 배지: WHITE~GOLD 모두 표시

### TC-04 학생 상세 탭
- 결제 탭: 2025-11~2026-01 이력 확인
- 레벨 탭: 7개 레벨(취득/미취득) 구분 확인
- 출석 탭: 월별 출석 현황 확인

### TC-05 학생 기본정보 수정
1. 학생 상세 → 수정
2. 이름/연락처/신발 사이즈 수정 후 저장
3. 목록/상세 즉시 반영 확인
4. 이름 빈 문자열 저장 시도 → 저장 차단 확인

### TC-06 시간표 수정 후 수업 재생성
1. 학생 상세에서 새 슬롯 추가(예: 금 17:00 일반1)
2. 저장
3. 설정에서 `2026-02` 수업 재생성
4. `2026-02-20` 금요일 17:00 수업 반영 확인
5. 중복 요일/시간 추가 시 DB unique 제약 오류 확인

### TC-07 상태 변경 반영
1. 재원 학생을 휴원으로 변경
2. 대시보드 재확인: 재원 -1 / 휴원 +1
3. 이달 미납 위젯에서 해당 학생 제외 확인
4. 원복

### TC-08 신규 학생 등록
1. 어린이 / 주2 / 화목 16:00 일반2 / 재원 등록
2. `2026-02` 수업 재생성
3. `2026-02-19` 목요일 16:00 일반2에 학생 표시 확인
4. 상세 출석 탭의 2026-02 예정 출석 확인

### 그룹 3. 레벨 테스트

### TC-09 레벨 테스트 대상자 표시
- 포함 기대:
- YELLOW 취득 2개월+ → GREEN 도전
- GREEN 취득 2개월+ (설정값에 따라 3개월+) → BLUE 도전
- BLUE 취득 3개월+ (설정값에 따라 4개월+) → RED 도전
- 미포함 기대:
- YELLOW 취득 1개월
- GOLD 학생
- 컬럼 확인: 이름/현재레벨/취득일/도전레벨/경과개월

### TC-10 레벨 테스트 통과 처리
1. 대상자 1명 선택
2. 학생 상세 → 레벨 이력 수정
3. 다음 레벨 취득일을 오늘로 저장
4. 검증:
- `student_levels` 취득일 업데이트
- `students.current_level` 업데이트
- 상세/목록 배지 반영

### TC-11 통과 후 다음 달 대상자 변화
1. TC-10 후 대시보드에서 해당 학생 제외 확인
2. 즉시 다음 도전 레벨로는 미표시 확인
3. 취득일을 과거 월로 조정 시 재표시 확인

### TC-12 레벨 테스트 미통과
1. 대상자 1명 선택
2. 수업 출석에 `is_test=true`만 기록
3. 레벨 취득일은 미변경
4. 다음 달에도 동일 도전 레벨 후보 유지 확인

### TC-13 GOLD 제외
1. GOLD 학생 존재 확인
2. 대시보드 후보 목록 미포함 확인
3. 상세 레벨 탭에서 7개 취득 완료 확인

### 그룹 4. 수업 관리

### TC-14 월별 수업 자동 생성
1. 설정 → `2026-03` → 수업 생성
2. 검증:
- classes 생성
- attendance(예정) 생성 (재원만)
- 재실행 시 중복 없음
3. 기대치: 재원 70명 기준 월 평균 약 560건 예정 출석

### TC-15 수업 수동 생성
1. 주차별 수업에서 빈 셀 `+`
2. 그룹 선택 후 생성
3. 주차/일별 양쪽에서 수업 카드 노출 확인

### TC-16 출석 처리
1. `2026-02-21` 일별 수업
2. 상태 토글: 예정 → 출석 → 결석 → 예정
3. 전체 출석 버튼 적용
4. 메모 저장 후 학생 상세 출석 탭 반영 확인

### 그룹 5. 보강 처리

### TC-17 결석 → 보강 연결
1. 학생 A 결석 처리
2. 다른 날짜 수업에서 학생 추가
3. 보강 체크 + 원 결석 선택
4. 검증:
- 새 attendance.status=`보강예정`
- `makeup_of_attendance_id` 연결
- 원 결석 유지

### TC-18 보강완료 처리
1. TC-17 레코드를 `보강완료`로 변경
2. 미처리보강 위젯에서 해당 결석 제거 확인
3. 학생 상세 출석 탭에 보강완료 표시 확인

### TC-19 보강 예외
- 결석 없는 학생의 보강 선택 목록 비어 있는지
- 이미 처리된 결석 재연결 제한/경고 여부
- 동일 학생 동일 수업 중복 추가 시 unique 오류

### 그룹 6. 체험 관리

### TC-20 체험 예약 흐름
1. 상태별 건수 확인: 예정(6) / 노쇼(4) / 미등록(5) / 등록(5)
2. 신규 체험 등록 저장 확인
3. 예정 → 등록 상태 변경 확인
4. 대시보드 오늘의 체험(`2026-02-21`) 2건 확인

## 3) 엣지 케이스 (TC-E1 ~ TC-E5)

### TC-E1 레벨 중간 건너뜀
- YELLOW 없이 GREEN 취득 입력
- 저장 시 최고 취득 레벨 기준으로 current_level 계산 확인

### TC-E2 시간표 중복
- 동일 요일/시간 중복 등록 시도
- unique(student_id, weekday, time) 오류 처리 확인

### TC-E3 결제 중복 월
- 동일 학생의 동일 target_month 결제 2건 입력
- 목록엔 2건 표시, 미납 위젯에서는 납부 처리되는지 확인

### TC-E4 퇴원 학생 이력
- 퇴원 학생 상세 출석 탭에서 퇴원 이전 이력 조회 확인

### TC-E5 주3회 초과 시간표
- sessions_per_week=3 학생에게 4개 시간표 시도
- UI 제한/경고 또는 저장 제한 확인

## 4) 운영 주의사항

- 스크립트는 기존 데이터 삭제 후 재삽입합니다(멱등).
- 삭제 대상: attendance → trial_reservations → classes → payments → student_levels → student_schedules → students
- branches 테이블은 유지하며, 기본 branch id는 upsert로 보장합니다.
- RLS가 활성화된 환경에서는 `SUPABASE_SERVICE_ROLE_KEY`가 필요할 수 있습니다.
